Why the gene -> protein edge is `biolink:has_gene_product`: in the BioLink model `translates_to` joins a transcript to a protein, and this graph has no transcript nodes, so the edge takes the BioLink predicate for gene -> product and keeps the brief's [http://purl.obolibrary.org/obo/so#translates_to](http://purl.obolibrary.org/obo/so#translates_to) on every such edge as `original_predicate`.
Why genes carry `SO:0001217`: the brief asks for the most specific class. BioLink has one Gene class, mapped to the general [http://purl.obolibrary.org/obo/SO_0000704](http://purl.obolibrary.org/obo/SO_0000704) (`SO:0000704`), so the specific term is set as the `type` of each protein-coding Gene node and overrides that default; every other Gene node carries the Sequence Ontology term of its own biotype.

Every class and predicate of the Pharos core and the enrichment layers below is a BioLink Model term (checked against the model file). The trial layer adds its own terms; they are listed, each with its BioLink parent, in the last section.

## Why these classes

- **As few as the identifiers allow.** 12 node classes and 13 predicates cover the Pharos core and every enrichment layer. A class exists only where an identifier prefix needs it: one BioLink class per prefix, the most specific one BioLink has for that prefix.
- **What was merged.** Layers disagree (one source lists some phenotype and GO terms as diseases); when the graphs are assembled 29,925 node rows are re-typed so that one identifier has one class everywhere. A disease term with an exact MONDO class is mapped to MONDO when its layer is built, so the same disease is one node.
- **Why 3 classes for the Gene Ontology.** GO has three separate branches and BioLink has one class for each (BiologicalProcess = `GO:0008150`, MolecularActivity = `GO:0003674`, CellularComponent = `GO:0005575`); folding them into one class would lose which kind of annotation an edge is (takes part in, is able to do, is located in).
- **Why DiseaseOrPhenotypicFeature next to Disease and PhenotypicFeature.** The 9,628 EFO terms without an exact MONDO class mix diseases, traits and measurements, and the identifier does not say which. Calling them all diseases would be a guess, so they keep the BioLink class that says exactly 'disease or phenotypic feature'.
- **Why two interaction predicates.** `directly_physically_interacts_with` is used where the source reports binding of a compound to its target; `physically_interacts_with` where a protein-protein source reports an interaction without saying the contact is direct. One predicate would overstate the second kind.

- pharos: BioPlex-only protein-protein rows: primary_knowledge_source infores:bioplex. The infores registry has no entry for BioPlex (data/reference/infores_checked.tsv); the id is kept and listed.
